**목표**
YouTube 게임 스트리밍 영상에서 `no-game 구간`을 먼저 제거하거나 약하게 배제하고, 남은 게임 구간에 대해서만 `video-based change point detection`을 적용해 연속 phase block으로 분할하는 가벼운 비지도 baseline을 만든다.

**핵심 아이디어**
이 계획은 역할을 분리한다.

- `Action data`: no-game 구간을 찾기 위한 저비용 1차 게이트
- `Video frames`: 게임 내부 phase 경계를 찾기 위한 주신호

즉, action으로 phase를 직접 나누지 않고, 먼저 `이 구간은 게임이 아닐 가능성이 높다`는 후보를 걸러낸 뒤, 실제 segmentation은 프레임 기반으로 수행한다.

**전체 파이프라인**
1. 시간 정렬된 `Video-Raw Action(Gamepad) Data`를 준비한다.
2. action 데이터를 window 단위로 요약해 `likely no-game` 구간을 찾는다.
3. `likely game + uncertain` 구간만 대상으로 프레임을 추출한다.
4. 추출된 프레임에서 visual feature를 뽑는다.
5. feature sequence에 대해 change point detection을 수행한다.
6. 너무 짧은 segment는 병합해 최종 phase block으로 정리한다.
7. 결과를 시간 구간 단위 JSON/CSV와 timeline 시각화로 저장한다.

**1단계: Action 기반 no-game 게이팅**
목적은 `완전한 게임/비게임 분류`가 아니라, `확실한 no-game만 보수적으로 제외`하는 것이다.

입력:
- 버튼 press/release
- 스틱 값
- 트리거 값
- timestamp

처리 방식:
- 현재 DB 기준으로는 `20초 chunk`를 window처럼 사용한다. 더 세밀한 `3~5초` 게이트는 raw action이 필요하다.
- 각 window마다 아래 통계를 계산한다.
  - 총 입력 수
  - 초당 입력 수
  - 버튼 종류 수
  - 입력 entropy
  - left/right stick movement magnitude
  - inactive duration
  - 연속 무입력 길이

판정 원칙:
- `장시간 거의 무입력`
- `입력량이 극히 낮고 다양성도 매우 낮은 상태가 지속`
- `스틱/버튼 활동이 거의 없는 구간이 길게 이어짐`

이런 구간만 `likely no-game`으로 표시한다.  
애매한 구간은 지우지 않고 남긴다.

중요한 제약:
- action 단계에서는 공격적으로 제거하지 않는다.
- 컷신, 로딩, 대기처럼 입력이 적은 게임 내부 구간을 실수로 삭제하면 이후 segmentation 품질이 무너진다.
- 따라서 이 단계는 `precision 우선`, 즉 확실한 no-game만 제외하는 게 맞다.

**2단계: Video 기반 phase segmentation**
action 게이트를 통과한 구간만 대상으로 프레임 기반 segmentation을 수행한다.

처리 방식:
- `1 fps` 또는 필요 시 `2 fps`로 프레임 추출
- 각 프레임에서 가벼운 visual embedding 추출
  - 시작점은 `CLIP ViT-B/32` 또는 동급 encoder
- feature를 시간축으로 smoothing
  - 예: `5~9초 moving average`
- change point detection 수행
  - 시작은 `ruptures` 기반 `Binseg`
  - 필요하면 `KernelCPD`나 `PELT` 비교

핵심 목적:
- 같은 시각적 상태가 이어지는 구간은 하나의 block으로 유지
- 메뉴, 로딩, 탐색, 전투, 화면 전환처럼 상태가 바뀌는 지점에서 경계 생성

**3단계: 후처리**
비지도 change point detection은 보통 과분할되므로 후처리가 필수다.

후처리 규칙:
- `20~30초 이하`의 매우 짧은 구간은 병합 후보로 본다.
- 인접 segment의 feature centroid가 충분히 비슷하면 병합한다.
- 경계가 지나치게 촘촘하면 약한 경계부터 제거한다.
- no-game으로 제외된 짧은 공백이 phase 사이에 끼어 있으면 필요 시 메운다.

목표는 raw change point를 그대로 쓰는 것이 아니라, 사람이 봐도 자연스러운 `phase block`으로 정리하는 것이다.

**출력 형식**
최종 출력은 라벨 없는 구간 목록이다.

예시:
```json
[
  {"start": 12.0, "end": 148.0, "phase_id": 1},
  {"start": 148.0, "end": 301.0, "phase_id": 2},
  {"start": 301.0, "end": 356.0, "phase_id": 3}
]
```

추가로 no-game 후보를 별도로 저장할 수 있다.

```json
[
  {"start": 0.0, "end": 12.0, "type": "no_game_candidate"},
  {"start": 356.0, "end": 402.0, "type": "no_game_candidate"}
]
```

**실험 순서**
1. action-only 게이트를 먼저 구현한다.
2. no-game 후보가 너무 공격적으로 잘리지 않는지 확인한다.
3. 통과 구간에 대해 video feature extraction을 붙인다.
4. `Binseg`로 가장 단순한 segmentation부터 확인한다.
5. smoothing, 최소 길이, 병합 기준만 조정한다.
6. 그 다음에야 fps나 encoder를 바꾼다.

이 순서가 중요한 이유는, 초기에 변수 수를 최소화해야 어느 단계가 잘못됐는지 바로 알 수 있기 때문이다.

**산출물**
각 실험마다 아래 4개는 반드시 남긴다.

- `segments.json`
- `nogame_candidates.json`
- `window_features.csv`
- `timeline_plot.png`

`timeline_plot`에는 최소한 아래가 있어야 한다.
- 시간축
- action activity score
- no-game 후보 구간
- visual change score
- 최종 boundary 위치

이 시각화가 있어야 threshold와 min-length를 조정할 수 있다.

**성공 기준**
이 baseline은 아래를 만족하면 성공이다.

- action 데이터만으로 확실한 no-game 후보를 무리 없이 걸러낸다.
- 전체 영상이 아니라 필요한 구간에만 프레임 처리를 수행해 비용을 줄인다.
- video feature 기반 change point detection이 사람이 납득 가능한 phase block을 만든다.
- 짧은 노이즈 segment가 후처리로 안정적으로 정리된다.
- 이후 필요하면 audio, OCR, richer video encoder를 붙일 수 있는 구조가 된다.

**한 줄 요약**
이 플랜은 `action으로 no-game 후보를 보수적으로 거른 뒤`, `남은 구간에 대해서만 프레임 기반 change point detection을 적용하고`, `짧은 조각을 병합해 최종 phase block을 만드는 hybrid 비지도 baseline`이다.

## DB 기준 action gate 구현 메모
- `video_chunks.duration`은 사실상 `20초` 고정이므로 현재 gate는 20초 chunk 기반이다.
- 기본 필드:
  - `action_density`
  - `button_count_total / chunk_size -> button_rate`
  - `sqrt(joy_x_std^2 + joy_y_std^2) -> joy_std_mag`
- strict no-game candidate rule:
  - `action_density <= 0.07`
  - `button_rate <= 0.03`
  - `joy_std_mag <= 0.06`
- fallback rule (`chunk_action_stats` 누락 시):
  - `action_density <= 0.03`
- 현재 구현 파일:
  - `scripts/build_action_nogame_gate.py`
  - `experiments/configs/action_nogame_gate.yaml`
