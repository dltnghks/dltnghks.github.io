# 데이터베이스

> [!summary] 한 줄 요약
> 데이터베이스는 프로그램의 데이터를 오래, 정확하고, 여러 사용자가 함께 사용할 수 있게 관리하는 기반이며, DBMS는 그 관리를 수행하는 소프트웨어다.

## 목차

1. 데이터베이스가 필요한 이유
2. 전체 흐름
3. 학습 지도
4. 모델을 고르는 기준
5. 자주 생기는 오해

## 1. 데이터베이스가 필요한 이유

서비스는 회원, 상품, 게시글, 결제, 로그처럼 시간이 지나도 남아야 하는 데이터를 다룬다. 일반 파일만으로도 데이터를 저장할 수는 있지만, 데이터가 커지고 여러 요청이 동시에 발생하면 다음 문제를 일관되게 처리하기 어렵다.

|필요한 능력|예시|
|---|---|
|빠른 조회|특정 회원의 주문 내역을 조건에 맞게 찾는다.|
|정확성|주문에 존재하지 않는 상품을 넣지 않는다.|
|동시성|마지막 재고 1개를 여러 사용자가 동시에 구매해도 수량이 음수가 되지 않게 한다.|
|복구|서버가 중간에 멈춰도 완료된 결제 기록을 잃지 않는다.|
|권한 관리|관리자만 개인정보를 조회·수정하게 한다.|

**데이터베이스(Database)** 는 조직적으로 저장된 데이터의 집합이고, **DBMS(Database Management System)** 는 저장·검색·변경·동시 접근·복구를 관리하는 소프트웨어다.

## 2. 전체 흐름

```text
사용자 요청
→ 애플리케이션의 읽기·쓰기 로직
→ DBMS가 스키마·권한·제약 조건을 확인
→ 트랜잭션으로 변경을 안전하게 처리
→ 데이터 저장 및 인덱스를 통한 조회
→ 결과를 애플리케이션에 반환
```

애플리케이션은 보통 DBMS에 질의하거나 변경을 요청하고, DBMS는 정해진 데이터 구조와 규칙을 바탕으로 그 요청을 수행한다. 변경 작업 여러 개가 하나의 업무 단위라면 **트랜잭션(Transaction)** 으로 묶어 모두 성공하거나 안전하게 취소되도록 다룬다.

> [!note] 관계형과 비관계형은 역할이 다를 수 있다
> 한 서비스가 하나만 써야 하는 것은 아니다. 주문·결제처럼 강한 정합성이 중요한 데이터는 관계형 DB를, 세션·캐시·검색 색인처럼 다른 접근 패턴이 중요한 데이터는 NoSQL을 함께 사용하는 경우도 많다.

## 4. 모델을 고르는 기준

저장 기술의 이름보다 **데이터의 관계**, **주요 읽기·쓰기 패턴**, **정합성 요구**, **데이터 규모와 분산 방식**을 먼저 묻는 편이 좋다.

|질문|관계형 DB가 잘 맞는 경우|NoSQL이 잘 맞을 수 있는 경우|
|---|---|---|
|데이터 관계는 어떤가?|여러 엔티티를 조인하고 참조 무결성을 지켜야 한다.|한 요청이 하나의 문서·키·그래프 이웃을 중심으로 접근한다.|
|구조는 얼마나 자주 바뀌는가?|공통된 구조와 규칙을 명확히 강제해야 한다.|레코드마다 속성이 크게 달라 유연한 구조가 유리하다.|
|정합성은 얼마나 중요한가?|금액·재고·권한처럼 오류 비용이 크다.|일부 데이터의 지연 반영을 감수하고 읽기·확장을 우선할 수 있다.|
|확장은 어떻게 하는가?|단일 시스템의 강한 일관성과 복잡한 질의가 중요하다.|대량 트래픽을 여러 노드에 분산하는 설계가 핵심이다.|

이는 단순한 경향이다. 관계형 DB도 수평 확장이 가능하고, 많은 NoSQL DB도 트랜잭션이나 스키마 검증을 제공한다. 실제 선택은 제품 기능과 운영 조건까지 확인해야 한다.

## 5. 자주 생기는 오해

### “데이터베이스는 파일보다 항상 빠르다”

DBMS는 인덱스, 버퍼 관리, 동시성 제어, 복구 같은 기능을 제공하는 대신 비용도 든다. 단순히 한 번 쓰고 읽는 작은 설정 파일이라면 파일이 더 단순할 수 있다. DBMS의 강점은 많은 데이터를 **규칙 있게, 동시에, 지속적으로** 다루는 데 있다.

### “NoSQL은 SQL을 전혀 못 쓴다”

NoSQL은 주로 관계형 테이블 모델을 쓰지 않는다는 뜻이다. 제품에 따라 SQL과 비슷한 질의 언어를 제공하거나 SQL을 지원할 수도 있다. 핵심 차이는 언어 이름보다 데이터 모델과 일관성·분산 설계다.

### “ACID는 관계형 DB에만 있다”

ACID는 신뢰할 수 있는 트랜잭션의 성질이다. 전통적으로 관계형 DB와 함께 많이 배우지만, 일부 NoSQL DB도 범위와 조건을 두고 트랜잭션을 지원한다. 지원 범위는 반드시 제품 문서와 실제 배포 구성을 확인해야 한다.
