## 핵심 개념

컴퓨터는 숫자나 글자를 직접 이해하지 않는다.
전기 신호의 두 상태를 0과 1로 약속하고, 이 비트의 조합을 정해진 규칙에 따라 해석한다.

## 1. 비트, 바이트, 2진수

### 비트와 바이트

**비트(bit)** 는 컴퓨터가 구분할 수 있는 가장 작은 정보 단위로, `0` 또는 `1` 하나를 표현한다.

**바이트(byte)** 는 일반적으로 8비트의 묶음이다. 8개의 비트가 각각 두 상태를 가질 수 있으므로, 1바이트는 총 $2^8 = 256$가지 값을 표현할 수 있다.

| 단위 | 비트 수 | 표현 가능한 경우의 수 |
| --- | ---: | ---: |
| 1비트 | 1 | 2개 |
| 1니블(nibble) | 4 | 16개 |
| 1바이트(byte) | 8 | 256개 |
| 2바이트 | 16 | 65,536개 |

> [!note] C 언어의 바이트
> 현대 컴퓨터에서는 보통 1바이트가 8비트다. 다만 C 언어에서 바이트는 `char` 하나의 크기를 뜻하며, 모든 환경에서 정확히 8비트여야 하는 것은 아니다.

### 2진수의 자릿값

10진수는 각 자리가 $1$, $10$, $100$처럼 10의 거듭제곱을 뜻한다.  
2진수는 각 자리가 $1$, $2$, $4$, $8$, $16$처럼 2의 거듭제곱을 뜻한다.

| 자리 | $2^3$ | $2^2$ | $2^1$ | $2^0$ |
| --- | ---: | ---: | ---: | ---: |
| 자릿값 | 8 | 4 | 2 | 1 |
| `1101₂` | 1 | 1 | 0 | 1 |

따라서 $1101_2 = 8 + 4 + 1 = 13_{10}$ 이다. 8비트로 표현하면 `13`은 `00001101`이다.

```text
128  64  32  16   8   4   2   1
 0   0   0   0   1   1   0   1

00001101₂ = 8 + 4 + 1 = 13₁₀
```

### n비트가 표현할 수 있는 범위

부호 없는 정수에서 n비트가 표현할 수 있는 값은 $0$부터 $2^n - 1$까지다.

|비트 수|표현 범위|
|---|---|
|4비트|0 ~ 15|
|8비트|0 ~ 255|
|16비트|0 ~ 65,535|

음수를 포함하는 부호 있는 정수는 뒤에서 2의 보수 방식으로 다룬다.

### 16진수

2진수는 길어지기 때문에 4비트씩 묶어 16진수로 자주 표현한다.

```
2진수:  0000 1101
16진수:    0    D

00001101₂ = 0x0D = 13₁₀
```

### C 예제: 정수 13을 비트열로 출력하기

```C
#include <stdint.h>
#include <stdio.h>

static void print_binary(uint8_t value) {
    for (int bit = 7; bit >= 0; --bit) {
        putchar((value & (1u << bit)) != 0 ? '1' : '0');
    }
}

int main(void) {
    uint8_t value = 13;

    printf("decimal: %u\n", (unsigned)value);
    printf("hex: 0x%02X\n", (unsigned)value);
    printf("binary: ");
    print_binary(value);
    putchar('\n');
}
```

```
decimal: 13
hex: 0x0D
binary: 00001101
```

`value`는 숫자 `13`으로 선언됐지만, 메모리에는 `00001101`이라는 비트 패턴으로 저장된다. 10진수·2진수·16진수는 같은 값을 서로 다르게 적는 표기법이다.

## 2. 비트열의 의미는 문맥이 결정한다

예를 들어 `11111111`은 해석 규칙에 따라 달라진다.

|해석 규칙|의미|
|---|---|
|부호 없는 8비트 정수|255|
|2의 보수 부호 있는 정수|-1|
|색상 채널 값|가장 강한 밝기|
|문자 인코딩의 일부|문자 데이터를 구성하는 바이트|

즉, 컴퓨터가 저장하는 것은 비트열이고, 그 비트열을 무엇으로 볼지는 프로그램과 데이터 형식이 결정한다.

## 3. 정보별 표현 방식

- 정수: 2진수와 부호 표현
- 문자: 문자 인코딩(ASCII, Unicode, UTF-8)
- 이미지: 픽셀마다 색상 값(RGB)을 저장
- 소리: 일정한 시간 간격으로 측정한 진폭 값(샘플)을 저장
- 프로그램: CPU가 실행할 명령어를 기계어 형태로 저장

### 3.1 현실의 정보는 비트열로 바뀐다

|단계|설명|예시|
|---|---|---|
|정보|사람이 다루는 의미 있는 대상|문자 `A`, 숫자 `65`, 사진, 소리|
|인코딩|정보를 비트열로 바꾸는 약속|ASCII, UTF-8, RGB, PCM|
|비트열|컴퓨터가 저장·계산·전송하는 형태|`01000001`|
|디코딩|비트열을 규칙에 따라 읽는 과정|문자 `A` 또는 숫자 `65`|

#### 같은 비트열도 해석 규칙에 따라 달라진다

|비트열|해석 규칙|의미|
|---|---|---|
|`01000001`|부호 없는 8비트 정수|65|
|`01000001`|ASCII 문자 코드|`A`|
|`01000001`|8비트 색상 채널 값|밝기 65|

### C17 예제: `0x41`을 숫자와 문자로 읽기

```
#include <stdint.h>
#include <stdio.h>

static void print_bits(uint8_t value) {
    for (int bit = 7; bit >= 0; --bit) {
        putchar((value & (1u << bit)) != 0 ? '1' : '0');
    }
}

int main(void) {
    uint8_t bits = 0x41;  // 01000001

    printf("bits: ");
    print_bits(bits);
    printf("\nnumber: %u\n", (unsigned)bits);
    printf("character: %c\n", (int)bits);
}
```

```
bits: 01000001
number: 65
character: A
```




### 3.2 정수 : 부호 없는 정수

**부호 없는 정수(unsigned integer)** 는 음수를 표현하지 않고, `0`과 양의 정수만 표현하는 방식이다.
모든 비트가 값의 크기를 표현하는데 사용된다.

n비트의 부호 없는 정수는 다음 범위를 표현한다.

$$
0 \sim 2^n - 1
$$

| 비트 수 | 최소값 | 최대값 |
| ---: | ---: | ---: |
| 4비트 | 0 | 15 |
| 8비트 | 0 | 255 |
| 16비트 | 0 | 65,535 |


8비트에서는 각 비트가 다음 값을 가진다.

```text
128  64  32  16   8   4   2   1
 0   0   0   0   1   1   0   1

00001101₂ = 8 + 4 + 1 = 13₁₀
```

가장 큰 8비트 부호 없는 정수는 모든 비트가 1인 경우다.

```
11111111₂ = 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1
          = 255₁₀
```
즉, 8비트에서는 256을 저장할 수 없다. 256은 2진수로 `1 00000000`이며, 표현하려면 9비트가 필요하다.

#### 범위를 넘으면 어떻게 될까?
8비트 값 `255`에 `1`을 더하면 계산 결과는 `256`이다. 하지만 저장 공간이 8비트뿐이라면 가장 왼쪽의 9번째 비트는 저장할 수 없고, 아래 8비트만 남는다.

```
  11111111  = 255
+ 00000001  =   1
----------
1 00000000  = 256

저장되는 하위 8비트: 00000000 = 0
```

이처럼 표현 범위를 넘어 값이 다시 처음으로 돌아가는 현상을 **오버플로(overflow)** 라고 한다.

### C17 예제: `uint8_t`의 범위

```C
#include <stdint.h>
#include <stdio.h>

static void print_binary(uint8_t value) {
    for (int bit = 7; bit >= 0; --bit) {
        putchar((value & (1u << bit)) != 0 ? '1' : '0');
    }
}

int main(void) {
    uint8_t maximum = UINT8_MAX;
    uint8_t wrapped = (uint8_t)((unsigned)maximum + 1u);

    printf("maximum: %u (", (unsigned)maximum);
    print_binary(maximum);
    printf(")\n");

    printf("after +1: %u (", (unsigned)wrapped);
    print_binary(wrapped);
    printf(")\n");
}
```

```
maximum: 255 (11111111)
after +1: 0 (00000000)
```
`uint8_t`는 정확히 8비트인 부호 없는 정수형이다. 위 코드에서 `255 + 1`의 결과인 `256`을 다시 `uint8_t`에 저장하면, C 언어 규칙에 따라 $256 \bmod 256 = 0$이 저장된다.

> [!warning] 부호 없는 정수는 음수를 표현하지 않는다  
> `11111111`은 부호 없는 8비트 정수로 해석하면 `255`이다. 같은 비트열을 부호 있는 정수로 해석하면 보통 `-1`이 될 수 있다.

### 3.3 정수: 부호 있는 정수와 2의 보수
부호 없는 정수는 `0`과 양수만 표현할 수 있다. 하지만 온도, 잔액, 좌표처럼 음수가 필요한 정보도 많다. **부호 있는 정수(signed integer)** 는 양수와 음수를 함께 표현하는 방식이다.
현대 컴퓨터는 대부분 **2의 보수(two's complement)** 를 사용한다.

#### 8비트 부호 있는 정수의 범위
8비트는 총 256가지 비트 패턴을 표현할 수 있다. 2의 보수에서는 이 패턴을 음수와 양수에 다음처럼 나눈다.

| 비트열 | 값 |
| --- | ---: |
| `00000000` | 0 |
| `01111111` | 127 |
| `10000000` | -128 |
| `11111111` | -1 |

따라서 8비트 부호 있는 정수의 범위는 다음과 같다.

$$
-128 \sim 127
$$

양수는 `0`부터 `127`까지 128개, 음수는 `-1`부터 `-128`까지 128개다. `+128`이 없기 때문에 범위가 완전히 대칭이지 않다.

#### 음수 만들기 : 비트를 반전하고 1을 더한다.

8비트에서 `-5`를 표현해 보자.
```text
 5  = 00000101
비트 반전 = 11111010
      +1 = 11111011

-5  = 11111011
```
같은 결과를 수식으로도 구할 수 있다.
$$ 2^8 - 5 = 256 - 5 = 251 $$
`251`의 2진수는 `11111011`이므로, 8비트 2의 보수에서 이 비트열은 `-5`를 뜻한다.

#### 최상위 비트의 의미

2의 보수에서는 최상위 비트가 단순히 “음수 표시”만 하는 것이 아니다. 8비트에서는 최상위 비트가 $-128$의 자릿값을 가진다.

```
11111011₂
= -128 + 64 + 32 + 16 + 8 + 2 + 1
= -5
```

#### 덧셈 회로로 뺄셈하기

2의 보수를 사용하면 덧셈 회로만으로 뺄셈을 처리할 수 있다.

```
  00000101  =  5
+ 11111011  = -5
----------
1 00000000

하위 8비트: 00000000 = 0
```

9번째 자리의 올림은 8비트 저장 공간에 들어가지 않는다. 따라서 `5 + (-5)`의 결과는 `0`이 된다.

### C17 예제: `-5`의 2의 보수 표현

```C
#include <stdint.h>
#include <stdio.h>

static void print_binary(uint8_t value) {
    for (int bit = 7; bit >= 0; --bit) {
        putchar((value & (1u << bit)) != 0 ? '1' : '0');
    }
}

int main(void) {
    int8_t signed_value = -5;
    uint8_t encoding = (uint8_t)signed_value;

    printf("signed value: %d\n", (int)signed_value);
    printf("unsigned encoding: %u\n", (unsigned)encoding);

    printf("bits: ");
    print_binary(encoding);
    putchar('\n');
}
```

```
signed value: -5
unsigned encoding: 251
bits: 11111011
```

`(uint8_t)signed_value` 변환은 `-5`에 256을 더한 `251`을 만든다. 일반적인 2의 보수 시스템에서 `251`의 비트열 `11111011`은 `int8_t`의 `-5`를 표현하는 방식과 같다.

> [!warning] C 언어의 부호 있는 오버플로  
> `int8_t`의 범위를 넘는 덧셈을 “비트가 한 바퀴 돌아간다”고 가정하면 안 된다. C에서 부호 있는 정수의 오버플로는 정의되지 않은 동작이다. 위 예제는 범위 안의 값과 부호 없는 변환만 사용하므로 안전하다.
### 3.4 실수 : 고정소수점과 부동소수점
정수는 비트로 정확하게 표현할 수 있지만, `13.25`, `0.1`, `-3.14`처럼 소수점이 있는 값은 별도의 표현 방식이 필요하다.
실수를 표현하는 대표적인 방식은 **고정소수점(fixed-point)**과 **부동소수점(floating-point)** 이다.

| 구분      | 고정소수점          | 부동소수점             |
| ------- | -------------- | ----------------- |
| 소수점 위치  | 항상 고정          | 지수에 따라 이동         |
| 표현 범위   | 비교적 작음         | 매우 넓음             |
| 정밀도     | 전체 범위에서 일정한 간격 | 값이 커질수록 표현 간격도 커짐 |
| 소수의 정확성 | 정한 단위 안에서는 정확  | 많은 10진수 소수가 근삿값   |
| 대표 용도   | 금액, 센서값, 임베디드  | 과학 계산, 그래픽, 머신러닝  |
#### 고정소수점
고정소수점은 소수점 위치를 미리 정한다. 예를 들어 금액을 원 단위 대신 센트 단위 정수로 저장할 수 있다.
```text
저장된 정수: 1325
소수점 위치: 뒤에서 두 자리
실제 값: 13.25
```

`1325`와 `75`를 더하면 정수 연산으로 정확히 `1400`을 얻는다. 이를 다시 소수점 둘째 자리로 읽으면 `14.00`이다.

고정소수점은 소수점 위치가 변하지 않으므로 이해하기 쉽고 일정한 단위의 값을 정확하게 다룰 수 있다. 반면 매우 큰 값과 매우 작은 값을 동시에 표현하기 어렵다.

> [!note] 고정소수점도 모든 소수를 정확히 표현하는 것은 아니다  
> 예를 들어 2진수 고정소수점은 `1/2`, `1/4`처럼 분모가 2의 거듭제곱인 값은 정확히 표현하지만, `0.1`은 정확히 표현할 수 없다. 금액을 센트 단위 정수로 저장하는 방식은 10진수 기준으로 소수 둘째 자리까지 정확하게 다루기 위한 별도의 스케일링 방법이다.

#### 부동소수점
부동소수점은 값을 다음과 같이 표현한다.

```
부호 × 유효숫자 × 2지수
```

10진수 과학적 표기법과 비슷하다.

```
1234.5 = 1.2345 × 10³
```

2진수에서는 `13.25`를 다음처럼 정규화한다.

```
13.25₁₀ = 1101.01₂
        = 1.10101₂ × 2³
```

`× 2³`은 이진 소수점을 오른쪽으로 세 칸 옮기는 것과 같다.

```
1.10101₂ × 2¹ = 11.0101₂
1.10101₂ × 2² = 110.101₂
1.10101₂ × 2³ = 1101.01₂
```

따라서 `1101.01₂`은 다음 값이다.

```
8 + 4 + 1 + 1/4 = 13.25
```

#### IEEE 754 단정도 `float`

현대 컴퓨터의 `float`은 대부분 IEEE 754 단정도 형식으로, 총 32비트를 사용한다.

|구성 요소|비트 수|역할|
|---|---|---|
|부호(sign)|1|양수 또는 음수|
|지수(exponent)|8|이진 소수점의 이동량|
|가수(fraction)|23|유효숫자의 세부 비트|

정규화된 일반 값은 다음 식으로 해석한다.

$$(-1)^S \times \left(1 + \frac{F}{2^{23}}\right) \times 2^{E-127}$$


- `S`: 부호 비트
- `F`: 가수 23비트를 부호 없는 정수로 읽은 값
- `E`: 저장된 지수 값
- `E - 127`: 실제 지수

지수는 8비트이므로 `0 ~ 255`을 저장할 수 있다. 하지만 `0`과 `255`은 0·무한대·NaN 같은 특수값에 사용된다.

```
일반적인 실제 지수 범위: -126 ~ +127
```

즉, 지수 8비트는 소수점을 8칸만 이동하는 것이 아니다. 일반적인 `float`은 이진 소수점을 왼쪽으로 최대 126칸, 오른쪽으로 최대 127칸 정도 이동할 수 있다.

#### `13.25`를 IEEE 754 방식으로 보기

```
13.25₁₀ = 1.10101₂ × 2³

부호: 0
실제 지수: 3
저장 지수: 3 + 127 = 130 = 10000010₂
가수: 10101000000000000000000
```

정규화된 수는 맨 앞의 `1`이 항상 존재하므로 저장하지 않는다. 따라서 가수 필드에는 `1.10101₂`에서 소수점 뒤의 `10101`만 저장한다.

#### 왜 `0.1`은 정확하지 않을까?

`0.1`은 2진수로 바꾸면 무한히 반복된다.

```
0.1₁₀ = 0.00011001100110011...₂
```

가수 필드는 유한한 23비트이므로, 컴퓨터는 반복되는 비트를 끝까지 저장할 수 없다. 가장 가까운 값으로 반올림해 저장한다.

따라서 다음 계산은 일반적인 환경에서 정확히 `0.3`이 아니다.

```
0.1 + 0.2 = 0.30000000000000004...
```



### C17 예제: 고정소수점과 부동소수점 비교

```C
#include <math.h>
#include <stdio.h>

int main(void) {
    /* 고정소수점: 100을 곱한 정수로 금액을 저장 */
    int price = 1325;      // 13.25
    int increase = 75;     // 0.75
    int total = price + increase;

    printf("fixed-point: %d.%02d\n",
           total / 100, total % 100);

    /* 부동소수점: 0.1을 정확히 저장하지 못할 수 있음 */
    double sum = 0.1 + 0.2;
    double target = 0.3;

    printf("floating-point: %.17g\n", sum);
    printf("exact equality: %s\n",
           sum == target ? "true" : "false");

    printf("within tolerance: %s\n",
           fabs(sum - target) < 1e-12 ? "true" : "false");
}
```

일반적인 IEEE 754 환경에서는 다음과 비슷하게 출력된다.

```
fixed-point: 14.00
floating-point: 0.30000000000000004
exact equality: false
within tolerance: true
```

> [!warning] 실수 비교  
> 부동소수점 값은 `==`로 직접 비교하지 않는 편이 안전하다. 두 값의 차이가 목적에 맞는 허용 오차보다 작은지 비교한다.


### 3.5 문자 : ASCII, Unicode, UTF-8
컴퓨터는 문자 `A`나 `가` 자체를 저장하지 않는다. 문자를 구분하기 위한 번호를 정하고, 그 번호를 다시 바이트열로 인코딩해 저장한다.

예를 들어 문자 `A`는 다음처럼 표현할 수 있다.

```
문자: A
Unicode 코드 포인트: U+0041
UTF-8 바이트: 0x41
2진수: 01000001
```

#### ASCII

ASCII는 영문 알파벳, 숫자, 기호, 제어 문자를 표현하기 위해 만든 문자 집합이다.

- 7비트 사용
- 총 128개 문자 표현
- 범위: `0 ~ 127`
- 영어 중심이라 한글·한자·이모지를 표현할 수 없음

|문자|10진수|16진수|2진수|
|---|---|---|---|
|`A`|65|`0x41`|`01000001`|
|`a`|97|`0x61`|`01100001`|
|`0`|48|`0x30`|`00110000`|

ASCII에서 `A`가 `65`인 이유는 문자 `A`에 65라는 번호를 약속했기 때문이다.

#### Unicode

Unicode는 전 세계 문자를 하나의 체계 안에서 다루기 위한 표준이다. 문자마다 **코드 포인트(code point)** 라는 고유 번호를 부여한다.

|문자|Unicode 코드 포인트|
|---|---|
|`A`|`U+0041`|
|`가`|`U+AC00`|
|`한`|`U+D55C`|
|`😊`|`U+1F60A`|

Unicode는 문자에 번호를 부여하는 표준일 뿐, 실제 메모리에 저장하는 바이트 형식을 정하는 것은 아니다.

#### UTF-8

UTF-8은 Unicode 코드 포인트를 바이트열로 저장하는 대표적인 인코딩 방식이다.

|문자 범위|UTF-8 바이트 수|비트 형태|
|---|---|---|
|ASCII 문자|1바이트|`0xxxxxxx`|
|일부 유럽 문자 등|2바이트|`110xxxxx 10xxxxxx`|
|한글·한자 등|3바이트|`1110xxxx 10xxxxxx 10xxxxxx`|
|일부 이모지 등|4바이트|`11110xxx 10xxxxxx 10xxxxxx 10xxxxxx`|

UTF-8은 ASCII와 호환된다. ASCII 범위의 문자는 기존 ASCII 값과 동일한 1바이트로 저장된다.

```
A   → U+0041 → 41
가  → U+AC00 → EA B0 80
😊  → U+1F60A → F0 9F 98 8A
```

따라서 UTF-8에서 문자열의 **바이트 수**와 **문자 수**는 다를 수 있다.

```
"A"  : 1글자, 1바이트
"가" : 1글자, 3바이트
"😊" : 1글자, 4바이트
```

### C17 예제: UTF-8 문자열은 바이트열이다

C의 일반 문자열은 문자 개수가 아니라 널 문자(`'\0'`)로 끝나는 **바이트열**이다. `strlen`은 UTF-8 문자의 개수가 아니라 바이트 수를 센다.

```C
#include <stdio.h>
#include <string.h>

int main(void) {
    const char *text = u8"가";

    printf("byte count: %zu\n", strlen(text));

    printf("UTF-8 bytes: ");
    for (size_t index = 0; index < strlen(text); ++index) {
        printf("%02X ", (unsigned int)(unsigned char)text[index]);
    }
    putchar('\n');
}
```

```
byte count: 3
UTF-8 bytes: EA B0 80
```

`가`는 사람이 보기에는 한 글자지만, UTF-8에서는 `EA B0 80`이라는 3바이트로 저장된다.

> [!warning] `strlen`은 글자 수를 세지 않는다  
> UTF-8 문자열에서 `strlen`은 바이트 수를 반환한다. 한글·이모지가 포함된 문자열의 글자 수를 세거나 특정 글자를 자르려면 UTF-8을 해석하는 별도 처리가 필요하다.

#### 정리
```
ASCII    : 영어 중심의 7비트 문자 집합
Unicode  : 전 세계 문자에 코드 포인트를 부여하는 표준
UTF-8    : Unicode 코드 포인트를 가변 길이 바이트열로 저장하는 인코딩
```





### 3.6 이미지 : 픽셀과 RGB로 색을 표현하는 방법
컴퓨터에서 이미지는 작은 점들의 격자인 **픽셀(pixel)** 로 표현한다. 각 픽셀은 화면의 한 위치와 그 위치의 색상 정보를 가진다.

이미지 = 가로 픽셀 수 × 세로 픽셀 수의 격자

예를 들어 Full HD 이미지는 다음과 같다.

```
1920 × 1080 = 2,073,600개의 픽셀
```

#### RGB 색상 모델

화면은 빛을 내므로, 보통 빨강(Red)·초록(Green)·파랑(Blue)을 섞는 RGB 색상 모델을 사용한다.

일반적인 이미지에서는 각 색상 채널에 8비트씩 사용한다.

|채널|비트 수|표현 범위|
|---|---|---|
|Red|8비트|0 ~ 255|
|Green|8비트|0 ~ 255|
|Blue|8비트|0 ~ 255|

따라서 한 픽셀은 총 24비트, 즉 3바이트를 사용한다.

```
R: 11111111 = 255
G: 00000000 = 0
B: 00000000 = 0

결과: 빨간색
```

|색상|RGB 값|16진수 표기|
|---|---|---|
|검정|`(0, 0, 0)`|`#000000`|
|흰색|`(255, 255, 255)`|`#FFFFFF`|
|빨강|`(255, 0, 0)`|`#FF0000`|
|초록|`(0, 255, 0)`|`#00FF00`|
|파랑|`(0, 0, 255)`|`#0000FF`|
|노랑|`(255, 255, 0)`|`#FFFF00`|

각 채널이 256가지 값을 표현할 수 있으므로, 24비트 RGB는 다음 색상 수를 표현할 수 있다.

\[ 256^3 = 16,777,216 \]

#### 해상도와 색 깊이

**해상도(resolution)** 는 이미지에 포함된 픽셀 수이고, **색 깊이(color depth)** 는 픽셀 하나의 색을 표현하는 데 사용하는 비트 수다.

```
해상도: 1920 × 1080
색 깊이: 24비트 RGB
```

압축하지 않은 RGB 이미지의 데이터 크기는 다음과 같이 계산할 수 있다.

\[ 가로 \times 세로 \times 픽셀당\ 바이트\ 수 \]

Full HD 24비트 RGB 이미지라면 다음과 같다.

```
1920 × 1080 × 3바이트
= 6,220,800바이트
≈ 5.93 MiB
```

PNG, JPEG 같은 이미지 파일은 압축 방식을 사용하므로 실제 파일 크기는 이 값과 다를 수 있다.

#### 알파 채널

투명도까지 표현하려면 알파(alpha) 채널을 추가한다.

```
RGBA = Red + Green + Blue + Alpha
```

일반적인 RGBA는 채널마다 8비트를 사용하므로 픽셀 하나가 4바이트다.

```
R: 색상 빨강
G: 색상 초록
B: 색상 파랑
A: 불투명도

A = 0   : 완전히 투명
A = 255 : 완전히 불투명
```

### C17 예제: RGB 값을 24비트 색상 코드로 묶기

```
#include <inttypes.h>
#include <stdint.h>
#include <stdio.h>

typedef struct {
    uint8_t red;
    uint8_t green;
    uint8_t blue;
} Rgb;

static uint32_t pack_rgb24(Rgb color) {
    return ((uint32_t)color.red << 16)
         | ((uint32_t)color.green << 8)
         | (uint32_t)color.blue;
}

int main(void) {
    Rgb yellow = {255, 255, 0};
    uint32_t packed = pack_rgb24(yellow);

    printf("R: %u, G: %u, B: %u\n",
           (unsigned)yellow.red,
           (unsigned)yellow.green,
           (unsigned)yellow.blue);

    printf("packed RGB: 0x%06" PRIX32 "\n", packed);
}
```

```
R: 255, G: 255, B: 0
packed RGB: 0xFFFF00
```

`0xFFFF00`은 `0xRRGGBB` 형식으로 색상을 적은 값이다.

```
RR = FF = 255
GG = FF = 255
BB = 00 = 0
```

> [!warning] 메모리의 실제 바이트 순서  
> `0xRRGGBB`은 색상을 설명하기 위한 일반적인 표기다. 실제 이미지 파일·그래픽 API·컴퓨터의 메모리에서는 RGB, BGR, RGBA처럼 채널 순서가 달라질 수 있다.

### 3.7 소리: 샘플링과 양자화로 소리를 표현하는 방법
현실의 소리는 시간에 따라 연속적으로 변하는 공기의 진동이ㅏ. 컴퓨터는 이 연속적인 파형을 일정한 시간 간격으로 측정해 숫자로 저장한다.

```
연속적인 소리 파형
        ↓ 샘플링
일정한 시간 간격의 측정값
        ↓ 양자화
정수 비트열
```
#### 샘플링
**샘플링(sampling)** 은 소리 파형의 진폭을 일정한 시간 간격으로 측정하는 과정이다.

**샘플링 주파수(sample rate)** 는 1초 동안 측정하는 횟수다.

|샘플링 주파수|의미|
|---|---|
|8,000 Hz|1초에 8,000번 측정|
|44,100 Hz|1초에 44,100번 측정|
|48,000 Hz|1초에 48,000번 측정|

CD 음질에서 자주 쓰는 `44.1 kHz`는 1초에 44,100개의 샘플을 저장한다는 뜻이다.

```
시간:     0초   1/44100초   2/44100초   3/44100초
진폭값:    0       1200        3100        5000
```

원래 파형을 충분히 복원하려면, 표현하려는 가장 높은 주파수의 최소 2배 이상으로 샘플링해야 한다. 이를 **나이퀴스트 샘플링 정리**라고 한다.

사람이 들을 수 있는 최대 주파수를 약 20 kHz로 보면, 44.1 kHz는 이를 표현하기에 충분한 샘플링 주파수다.

#### 양자화
**양자화(quantization)** 는 측정한 연속적인 진폭값을 정해진 단계의 정수값으로 바꾸는 과정이다.

예를 들어 16비트 PCM은 진폭을 다음 범위의 부호 있는 정수로 저장한다.

```
-32,768 ~ 32,767
```

|비트 깊이|표현 가능한 진폭 단계 수|
|---|---|
|8비트|256개|
|16비트|65,536개|
|24비트|16,777,216개|

비트 깊이가 클수록 진폭을 더 세밀하게 나눌 수 있어, 원래 파형과의 차이가 줄어든다.

```
연속 진폭: 0.5000
16비트 정수값: 약 16,384
```


#### 채널
**채널(channel)** 은 독립적인 소리 신호의 개수다.

|채널 구성|채널 수|예시|
|---|---|---|
|모노|1|음성 녹음|
|스테레오|2|일반 음악|
|5.1채널|6|영화·서라운드 사운드|

스테레오는 왼쪽과 오른쪽 채널을 따로 저장하므로, 모노보다 같은 시간에 2배 많은 샘플 데이터를 사용한다.


#### 비트레이트와 파일 크기
압축하지 않은 PCM 오디오의 비트레이트는 다음 식으로 계산한다.

$샘플링\ 주파수 \times 비트\ 깊이 \times 채널 수$

CD 음질 스테레오 PCM의 경우:

```
44,100 × 16 × 2
= 1,411,200 bit/s
= 1,411.2 kbps
```

이는 초당 176,400바이트, 약 176.4 kB의 데이터다.

```
3분 음악의 PCM 데이터 크기
= 176,400 × 180초
= 31,752,000바이트
≈ 30.3 MiB
```

WAV는 PCM 같은 원시 오디오 데이터를 담을 수 있는 컨테이너 형식이다. MP3, AAC 같은 형식은 사람이 잘 느끼지 못하는 정보를 줄여 파일 크기를 작게 만드는 손실 압축 방식이다.

### 3.8 프로그램 : 명령어가 비트열로 표현되는 방법
프로그램도 결국 비트열이다. 다만 문자, 이미지, 소리와 달리, 프로그램의 비트열은 CPU가 **실행할 명령어**로 해석된다.

```
C 소스 코드
   ↓ 컴파일
어셈블리 코드
   ↓ 어셈블
기계어
   ↓ 로드
메모리에 저장된 명령어 비트열
   ↓
CPU가 인출·해독·실행
```
#### C코드와 기계어
C코드는 사람이 읽기 쉬운 텍스트다.
```C
int add(int left, int right){
	return left+right;
}
```
CPU는 `int`, `return`, `+` 같은 C언어 문법을 직접 이해하지 못한다. 컴파일러가 이 코드를 CPU가 이해하는 기계어 명령어로 변환한다.

같은 C코드라도 대상 CPU에 따라 생성되는 기계어는 달라질 수 있다.
```
C 코드
 ├─ x86-64용 컴파일 → x86-64 기계어
 └─ ARM64용 컴파일  → ARM64 기계어
```

> [!note] C 코드와 기계어는 일대일이 아니다  
> C 코드 한 줄이 기계어 한 명령어가 되는 것은 아니다. 컴파일러의 최적화, 함수 호출 규약, 대상 CPU 구조에 따라 여러 명령어가 만들어지거나 일부 코드가 사라질 수 있다.

#### 명령어의 구성
기계어 명령어에는 보통 다음 정보가 들어 있다.

|구성 요소|역할|
|---|---|
|연산 코드(opcode)|덧셈, 뺄셈, 비교, 이동 등 수행할 작업|
|피연산자(operand)|연산에 사용할 값·레지스터·메모리 위치|
|목적지(destination)|결과를 저장할 위치|
|즉시값(immediate)|명령어 안에 직접 포함된 상수|
다음은 이해를 위한 가상의 명령어 형식이다.
```
[ opcode | destination | source 1 | source 2 ]
ADD R1, R2, R3
```
위 명령어는 `R2`와 `R3`의 값을 더해 `R1`에 저장하라는 뜻이다. 실제 CPU마다 비트 수와 명령어 형식은 다르다.

#### CPU는 프로그램을 어떻게 실행할가?
프로그램이 실행되면 운영체제는 실행 파일의 기계어와 데이터를 메모리에 올린다. CPU는 프로그램 카운터(PC)가 가리키는 위치에서 다음 명령어를 반복해서 처리한다.

```
1. 인출(fetch)
   메모리에서 명령어 비트열을 가져온다.

2. 해독(decode)
   비트열을 opcode와 피연산자로 나눈다.

3. 실행(execute)
   ALU, 레지스터, 메모리 등을 사용해 작업한다.

4. 결과 저장(write-back)
   결과를 레지스터나 메모리에 저장한다.

5. 다음 명령어로 이동
   PC를 변경하고 다시 반복한다.
```

따라서 데이터와 프로그램은 모두 비트열이지만, CPU는 현재 위치와 명령어 형식에 따라 비트열을 “실행할 명령어” 또는 “처리할 데이터”로 구분한다.


### C17 예제: 소스 코드에서 어셈블리 확인하기

아래 C 파일을 `add.c`로 저장했다고 가정한다.

```
int add(int left, int right) {
    return left + right;
}

int main(void) {
    return add(3, 4);
}
```

다음 명령은 컴파일 결과를 실행 파일 대신 어셈블리 파일로 생성한다.

```
cc -std=c17 -O0 -S add.c
```

생성되는 어셈블리 내용은 컴파일러와 CPU에 따라 다르다. 예를 들어 x86-64와 ARM64는 서로 다른 레지스터 이름과 서로 다른 명령어 비트열을 사용한다.

> [!warning] 기계어는 CPU마다 다르다  
> x86-64용 실행 파일을 ARM64 CPU가 직접 실행할 수는 없다. CPU가 이해하는 명령어 집합(ISA)이 다르기 때문이다.

## 4. 정리

컴퓨터가 실제로 다루는 것은 0과 1의 비트열이다.  
숫자, 문자, 이미지, 소리, 명령어는 모두 비트열을 해석하는 방식의 차이일 뿐이다.
