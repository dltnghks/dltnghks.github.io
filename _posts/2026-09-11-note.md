## 1. 네트워크가 하는 일

네트워크의 목적은 한 장치에서 만든 데이터를 다른 장치 또는 프로그램까지 전달하는 것이다. 단순히 선이나 전파로 데이터를 보내는 것만으로는 충분하지 않다. 네트워크는 다음 문제를 함께 해결해야 한다.

| 질문 | 네트워크가 제공하는 것 |
|---|---|
| 누구에게 보내는가? | 이름, IP 주소, 포트로 목적지를 식별한다. |
| 어디로 보내는가? | 라우터가 목적지까지의 전달 경로를 결정한다. |
| 어떤 형태로 보내는가? | 계층별 프로토콜이 데이터를 알맞은 단위로 포장한다. |
| 올바르게 도착했는가? | 오류 검출, 재전송, 순서 제어 등을 수행한다. |
| 얼마나 빠르고 안정적인가? | 혼잡 제어, 부하 분산, 장애 우회 등을 이용한다. |

네트워크의 규모는 집 안의 Wi-Fi처럼 작을 수도 있고, 전 세계의 수많은 네트워크가 연결된 인터넷처럼 클 수도 있다.

> [!note] 인터넷과 웹은 다르다
> **인터넷(Internet)**은 여러 네트워크를 연결하는 기반 구조이고, **웹(Web)**은 그 위에서 HTTP 등의 프로토콜로 문서를 주고받는 서비스다. 이메일, 온라인 게임, 화상 통화도 인터넷을 사용하지만 웹 자체는 아니다.

## 2. 데이터가 이동하는 과정

사용자가 브라우저에서 웹 페이지를 열면, 애플리케이션이 만든 요청은 여러 계층을 거치며 목적지 서버로 전달된다.

```text
애플리케이션 메시지
→ 전송 계층 데이터
→ IP 패킷
→ 링크 계층 프레임
→ 전기·빛·무선 신호
→ 네트워크를 통과
→ 수신 측에서 역순으로 해석
```
송신 측은 데이터를 아래 계층으로 전달하면서 각 계층에 필요한 제어 정보를 붙인다. 이를 **캡슐화(Encapsulation)** 라고 한다. 수신 측은 반대로 제어 정보를 제거하고 해석하는 **역캡슐화(Decapsulation)** 를 수행한다.

|단계|송신 측에서 하는 일|수신 측에서 하는 일|
|---|---|---|
|응용|요청·메시지 형식을 만든다.|메시지의 의미를 해석한다.|
|전송|포트, 신뢰성, 순서 등의 정보를 붙인다.|올바른 프로그램에 데이터를 전달한다.|
|인터넷|출발지·목적지 IP 주소를 붙인다.|목적지 IP인지 확인한다.|
|링크|현재 네트워크 구간을 위한 프레임을 만든다.|프레임 오류를 확인하고 상위 계층으로 넘긴다.|
|물리|비트를 신호로 변환한다.|신호를 비트로 복원한다.|

> [!warning] 단순화한 모델  
> 계층의 정확한 구분과 데이터 단위의 명칭은 OSI 모델, TCP/IP 모델, 실제 구현에 따라 조금씩 다르다. 여기서는 통신 흐름을 이해하기 위한 대표적인 모델로 사용한다.

## 3. 네트워크를 구성하는 요소

### 호스트(Host)

네트워크에 연결되어 데이터를 보내거나 받는 장치다. PC, 스마트폰, 서버, IoT 기기 등이 호스트가 될 수 있다.

- **클라이언트(Client)**: 서비스를 요청하는 쪽
- **서버(Server)**: 요청을 처리하고 응답하는 쪽

클라이언트와 서버는 장치의 고정된 종류가 아니라 통신 상황에서의 역할이다. 한 장치가 상황에 따라 두 역할을 모두 수행할 수도 있다.

### 스위치(Switch)

같은 LAN(Local Area Network) 안에서 장치를 연결한다. 일반적으로 MAC 주소를 기준으로 프레임을 적절한 포트로 전달한다.

### 라우터(Router)

서로 다른 네트워크 사이에서 IP 패킷을 전달한다. 라우터는 라우팅 테이블과 정책을 바탕으로 다음 전달 지점을 선택한다.

> [!tip] 라우터는 “가장 짧은 길”만 고르지 않는다  
> 실제 경로 선택에는 거리뿐 아니라 비용, 장애 상태, 사업자 정책, 보안 정책 등이 영향을 줄 수 있다.

### 액세스 포인트와 모뎀

- **액세스 포인트(AP)**: Wi-Fi 장치를 유선 네트워크에 연결한다.
- **모뎀(Modem)**: 통신 회선의 신호 방식에 맞춰 데이터를 변환한다.
- 가정용 공유기는 라우터, 스위치, 액세스 포인트 기능을 하나의 장치에 함께 제공하는 경우가 많다.

### DNS 서버

사람이 읽기 쉬운 도메인 이름을 IP 주소로 변환한다.

```
www.example.com
→ DNS 질의
→ 93.184.216.34 같은 IP 주소 획득
→ 해당 서버에 연결 시도
```

## 4. 계층으로 나누는 이유

네트워크는 매우 복잡하다. 무선 신호의 전달 방식, 다른 네트워크로 가는 경로, 데이터의 재전송, 웹 페이지 형식까지 하나의 규칙으로 처리하면 변경과 관리가 어려워진다.

그래서 네트워크는 역할을 나눈 계층 구조를 사용한다.

|계층|핵심 책임|대표 예시|
|---|---|---|
|응용 계층|사용자와 서비스에 가까운 데이터 형식|HTTP, DNS, SMTP|
|전송 계층|프로그램 간 통신, 포트, 신뢰성|TCP, UDP, QUIC|
|인터넷 계층|네트워크 간 전달과 IP 주소|IP, ICMP|
|링크 계층|같은 네트워크 구간에서의 전달|Ethernet, Wi-Fi|
|물리 계층|비트를 실제 신호로 전달|케이블, 광섬유, 무선 전파|

계층화의 장점은 다음과 같다.

- 한 계층의 구현을 바꾸어도 다른 계층에 미치는 영향을 줄일 수 있다.
- 서로 다른 제조사와 운영체제도 공통 프로토콜을 따르면 통신할 수 있다.
- 문제 발생 지점을 계층별로 나누어 진단할 수 있다.
- 새로운 서비스와 전송 기술을 비교적 독립적으로 발전시킬 수 있다.

계층별 역할과 캡슐화는 [[네트워크 계층 구조]]에서 자세히 다룬다.

## 5. 주소와 이름: 목적지를 찾는 방법

통신에는 하나의 주소만 사용되지 않는다. 각 주소는 서로 다른 범위와 목적을 가진다.

|식별자|예시|역할|주 사용 범위|
|---|---|---|---|
|도메인 이름|`example.com`|사람이 읽기 쉬운 서비스 이름|인터넷 서비스|
|IP 주소|`203.0.113.10`|네트워크상 호스트의 논리적 위치|네트워크 간 전달|
|포트 번호|`443`, `53`|호스트 안의 특정 프로그램 식별|호스트 내부|
|MAC 주소|`00:1A:2B:...`|링크 구간의 네트워크 인터페이스 식별|같은 LAN 구간|

이 식별자들은 서로 경쟁하지 않고 협력한다.

```
도메인 이름
→ DNS가 IP 주소를 찾음
→ IP 주소를 기준으로 인터넷을 통과
→ 목적지 호스트의 포트로 전달
→ 같은 링크 구간에서는 MAC 주소를 사용
```

> [!note] ARP와 NDP  
> IPv4 환경에서는 일반적으로 **ARP**가 IP 주소에 대응하는 MAC 주소를 찾는다. IPv6에서는 같은 목적을 위해 주로 **NDP(Neighbor Discovery Protocol)**를 사용한다.

## 6. 핵심 프로토콜

프로토콜은 통신 참여자가 따라야 하는 약속이다. 데이터 형식, 요청과 응답의 순서, 오류 처리 방식 등을 정의한다.

|범주|프로토콜|역할|
|---|---|---|
|이름 해석|DNS|도메인 이름을 IP 주소로 변환한다.|
|웹|HTTP|웹 요청과 응답의 형식을 정의한다.|
|보안|TLS|통신 내용을 암호화하고 상대를 검증한다.|
|신뢰성 전송|TCP|순서 보장, 재전송, 흐름·혼잡 제어를 제공한다.|
|빠른 전송|UDP|최소한의 제어 정보로 데이터를 전달한다.|
|현대적 전송|QUIC|UDP 위에서 연결 설정, 암호화, 다중화 기능을 제공한다.|
|인터넷 전달|IP|서로 다른 네트워크 사이에서 패킷을 전달한다.|
|진단|ICMP|오류 알림과 네트워크 진단에 사용된다.|
|링크 전달|Ethernet, Wi-Fi|같은 네트워크 구간에서 프레임을 전달한다.|
|주소 설정|DHCP|장치에 IP 주소 등 네트워크 설정을 제공한다.|

> [!important] TCP와 IP의 책임은 다르다  
> **IP**는 목적지까지 패킷을 전달하기 위한 기본 구조를 제공하지만, 일반적으로 전달 성공·순서·중복 제거를 보장하지 않는다. **TCP**는 종단 호스트 사이에서 이러한 신뢰성 기능을 제공한다.

프로토콜별 동작과 선택 기준은 [[핵심 프로토콜]]에서 다룬다.

## 7. 트래픽, 성능, 안정성

네트워크 품질은 단순히 “인터넷이 빠르다”로 설명하기 어렵다. 서비스 종류에 따라 중요한 지표가 다르다.

|지표|의미|특히 중요한 서비스|
|---|---|---|
|대역폭(Bandwidth)|이론적으로 전송할 수 있는 최대 용량|대용량 다운로드, 영상 전송|
|처리량(Throughput)|실제로 전송된 데이터량|모든 서비스|
|지연 시간(Latency)|데이터가 목적지에 도달하는 데 걸리는 시간|게임, 원격 제어|
|RTT|요청과 응답이 왕복하는 시간|웹, API, 게임|
|지터(Jitter)|지연 시간의 흔들림|음성·화상 통화|
|패킷 손실(Packet Loss)|전송 중 유실된 데이터의 비율|실시간 통신, 스트리밍|
|가용성(Availability)|서비스를 정상적으로 사용할 수 있는 비율|모든 운영 서비스|

### 혼잡

여러 사용자가 제한된 네트워크 자원을 동시에 사용하면 패킷이 장비의 대기열에 쌓인다. 대기열이 길어지면 지연이 증가하고, 버퍼가 가득 차면 패킷 손실이 발생한다.

```
트래픽 증가
→ 대기열 증가
→ 지연 증가
→ 버퍼 초과
→ 패킷 손실
→ 재전송 또는 품질 저하
```

### 안정성을 높이는 방법

- **재전송**: 손실된 데이터를 다시 보낸다.
- **흐름 제어**: 수신 측이 처리할 수 있는 속도를 넘지 않도록 조절한다.
- **혼잡 제어**: 네트워크가 감당할 수 있는 수준으로 전송량을 조절한다.
- **부하 분산**: 요청을 여러 서버나 경로에 나눈다.
- **중복 구성**: 장비·경로·서버 일부에 장애가 생겨도 서비스를 유지한다.
- **캐시와 CDN**: 사용자 가까이에 데이터를 배치해 지연과 원본 서버 부하를 줄인다.
- **모니터링**: 지연, 손실, 오류율, 가용성을 관찰해 장애를 빠르게 감지한다.

트래픽 측정, 혼잡, 장애 대응은 [[트래픽 및 안정성]]에서 이어서 다룬다.

## 8. 웹 페이지 요청으로 보는 전체 흐름

브라우저에서 `https://example.com`을 입력했을 때의 흐름을 단순화하면 다음과 같다.

1. 브라우저는 DNS를 통해 도메인 이름에 대응하는 IP 주소를 찾는다.
2. 브라우저는 서버와 연결을 준비한다.
    - HTTP/1.1, HTTP/2에서는 일반적으로 TCP 연결 뒤 TLS를 사용한다.
    - HTTP/3에서는 일반적으로 QUIC와 TLS를 사용한다.
3. 브라우저는 HTTP 요청을 만든다.
4. 운영체제의 네트워크 계층은 요청을 전송 계층 데이터, IP 패킷, 링크 계층 프레임으로 포장한다.
5. 프레임은 로컬 네트워크의 스위치·공유기·라우터를 거쳐 인터넷으로 나간다.
6. 중간 라우터들은 목적지 IP 주소를 기준으로 다음 경로를 선택한다.
7. 서버는 데이터를 역순으로 해석하고, 웹 서버 프로그램이 HTTP 요청을 처리한다.
8. 서버의 응답도 같은 원리로 브라우저까지 되돌아온다.
9. 브라우저는 HTML, CSS, JavaScript, 이미지 등의 응답을 해석해 화면을 만든다.

```
브라우저
→ DNS
→ 연결 준비
→ HTTP 요청
→ IP 패킷 전달
→ 서버 처리
→ HTTP 응답
→ 브라우저 렌더링
```

## 9. 자주 생기는 오해

### “IP 주소만 알면 바로 상대방에게 간다”

IP 주소는 목적지를 식별하는 핵심 정보지만, 실제 전달은 여러 라우터와 링크를 거쳐 이루어진다. 각 라우터는 전체 경로가 아니라 다음 전달 지점(Next Hop)을 선택하는 방식으로 동작한다.

### “TCP 연결은 전용 회선이다”

TCP 연결은 양 끝 호스트가 통신 상태를 관리하는 논리적 연결이다. 인터넷 중간의 패킷은 같은 물리적 전용 선로를 계속 사용하는 것이 아니며, 네트워크 상황에 따라 경로가 달라질 수 있다.

### “패킷이 손실되면 항상 실패한다”

TCP 기반 통신은 손실을 감지하면 재전송을 시도한다. 반면 실시간 음성·영상처럼 늦게 도착한 데이터의 가치가 낮은 서비스는 UDP 등을 사용하고, 일부 손실을 허용하면서 지연을 줄이기도 한다.

### “Wi-Fi가 느리면 인터넷 자체가 느린 것이다”

문제는 여러 구간에서 발생할 수 있다.

```
내 기기
→ Wi-Fi
→ 공유기
→ 인터넷 서비스 제공자
→ 인터넷 경로
→ 서버
```

따라서 속도 저하를 진단할 때는 무선 신호, 로컬 네트워크, DNS, 서버 응답 시간, 인터넷 경로를 나누어 확인해야 한다.
