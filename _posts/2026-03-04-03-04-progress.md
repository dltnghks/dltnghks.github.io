## 1) FiLM: 액션이 “스케일/시프트”로 특징을 조절

### 형태
$$
(\gamma,\beta)=\text{MLP}(e_a,e_\Delta),\quad \tilde z=\gamma\odot z+\beta  
$$

- 액션이 각 feature 차원에 대해 **곱(스케일)과 더하기(시프트)** 로 “게이트”를 건다. 
- 보통 **z가 1개 벡터**(클립 임베딩)일 때 깔끔.

### 장점
- **가볍다**: 연산/메모리 매우 작음
- **안정적**: 튜닝 포인트 적고 수렴이 잘 됨
- **조건 주입이 명확**: “액션이 상태 표현을 어떻게 변형하는지”가 직관적
    
### 단점
- 표현력 제한: 기본적으로 **차원별(대각) 변환**에 가까움  
    (비선형 MLP를 붙여도, 구조적으로 “토큰 간 정렬/매칭” 같은 건 약함)

## 2) Cross-Attention Fusion: 액션 토큰을 “참조”해서 비전 토큰을 업데이트

### 형태(개념)
- 비전 토큰(시간/공간): (Z\in\mathbb{R}^{N\times d})
- 액션 토큰: (A\in\mathbb{R}^{M\times d})
- 비전 토큰이 액션 토큰을 키/밸류로 두고 attention:  
    $$
    Z' = \text{Attn}(Q=Z,\ K=A,\ V=A)  
    $$
    

### 장점
- **표현력 최고**:
    - 특정 시간 구간의 액션이 특정 프레임 특징에 미치는 영향
    - 버튼 이벤트(attack)와 화면 변화(이펙트) 같은 **정렬(alignment)**
    - “어떤 액션 토큰을 참고해야 하는지”를 학습 가능    
    
- 액션이 시퀀스일 때 특히 강함(프레임별 액션-프레임별 시각의 대응)


### 단점
- **비싸다**: 토큰 수 (N) (프레임×패치 등) 커지면 비용 증가
- **구현/튜닝 부담**: 토큰 설계, positional encoding, 안정화(정규화 등) 포인트가 늘어남
- 데이터가 noisy하면 attention이 “편법 토큰”(HUD 등)으로 새기도 쉬움 → 증강/마스킹 더 중요

## 3) 너 세팅에서 언제 뭐가 맞나

### FiLM이 좋은 경우(너한테 기본 추천)

- 시작 단계(단일 프레임 또는 프레임당 1개 벡터)
- 계산을 아끼고 싶음
- 액션을 “조건”으로만 주입하면 충분 (국면/동역학 신호는 시간 Δ와 미래 예측으로 확보)
    

### Cross-attention이 좋은 경우

- 비전을 **토큰 시퀀스**로 쓴다 (프레임별 벡터들 (L\times d) 또는 패치 토큰) 
- 액션도 **시퀀스**로 쓴다 (프레임별 스틱/버튼 이벤트)
- “타이밍/정렬”이 중요한 상호작용을 더 정확히 담고 싶다  
    (예: 버튼 눌림 직후 3프레임에서 이펙트가 터짐)

# 게임 내 trajectory 구분

**① Pixel diff**
```python
δ_pixel[t] = mean(|s_{t+1} - s_t|)
```

**② Histogram diff**
```python
δ_hist[t] = KL(H(s_t) || H(s_{t+1}))
```

**③ Action 기반**
```python
# action이 갑자기 없거나 (컷씬, 로딩)
# action은 있는데 픽셀 변화가 과도하게 큼 (순간이동)
δ_action[t] = 1  if a_t == null
              1  if (a_t != null) and (δ_pixel[t] > threshold_high)
              0  otherwise
```

이 3가지를 가지고 앙상블해서 구분하기
```python
is_transition[t] = (δ_pixel[t] > θ_p) OR
                   (δ_hist[t]  > θ_h) OR
                   (δ_action[t] == 1)

```
원본:   s1  s2  s3  [전환]  s4  s5  s6  s7  [전환]  s8  s9  s10
분할:   traj_1 = [s1, s2, s3]
        traj_2 = [s4, s5, s6, s7]
        traj_3 = [s8, s9, s10]

# ConvNeXt
2020년 ViT(Vision Transformer)가 등장하면서 CNN 계열이 밀리기 시작했다.

```
기존 흐름:  ResNet (CNN) → 성능 한계
새로운 흐름: ViT (Transformer) → 높은 성능, 하지만 데이터 많이 필요
```

Meta AI의 Liu et al. (2022)이 의문을 제기

> **"ViT가 좋은 게 Transformer 구조 덕분인가, 아니면 설계 디테일 덕분인가?"**

ResNet에 ViT의 설계 요소들을 하나씩 이식해보면서 어떤 게 성능에 기여하는지 분석

---

## ResNet → ConvNeXt 현대화 과정

```
ResNet-50 (76.1%)
    ↓ 학습 전략 개선 (epoch, augmentation 등)
78.8%
    ↓ stage 비율 조정 (3,4,6,3 → 3,3,9,3)
79.4%
    ↓ patchify stem (7×7+maxpool → 4×4 conv)
79.5%
    ↓ depthwise conv + inverted bottleneck
80.6%
    ↓ 7×7 depthwise conv (kernel 키우기)
80.6%
    ↓ BN → LN, ReLU → GELU
81.3%
    ↓ activation/norm 개수 줄이기
82.0%
ConvNeXt-T (82.1%)
```
