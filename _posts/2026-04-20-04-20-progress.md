## 실험 전체 정리

---

### 배경 및 목표

**파이프라인**: MFCC → SSM (Self-Similarity Matrix) → Checkerboard Kernel → Novelty Curve → Peak Detection → 경계 시간

**데이터셋**:

- Train: Action RPG 3개 게임 (Game A/B/C), 35 clips
- Annotation: 3명 annotator, tolerance=2s, min_agreement=2
- 평가 지표: Macro F1 (클립별 F1 평균)

---

### 실험 1: n_mfcc Ablation

**목적**: MFCC 계수 수가 성능에 영향을 주는지 확인 → n_mfcc 고정 근거 마련

**방법**: n_mfcc = {13, 20, 40}별로 나머지 파라미터 grid search 후 best F1 비교

|n_mfcc|Best F1|Mean F1|
|---|---|---|
|13|0.545|0.433|
|20|0.546|0.434|
|40|0.537|0.431|

**결론**: 차이 0.01 이내 → **n_mfcc=13 고정** (계산 비용 대비 이득 없음)

### 실험 2: Baseline Parameter 탐색 (Method A)

**목적**: Mixture 단일 스트림 최적 파라미터 확정

**핵심 설계 결정**:

- Kernel Size를 고정값(k=10)이 아닌 **시간 기반**으로 변경
    - `KS = max(2, round(KS_SEC / HS))`
    - 이유: 클립 길이와 무관하게 동일한 시간 스케일(±KS_SEC초) 커버

**탐색 파라미터 및 범위**:

|파라미터|범위|의미|
|---|---|---|
|WS|0.5~3.0s|SSM 세그먼트 윈도우 크기|
|HS|0.25~1.0s|SSM 해상도|
|KS_SEC|2~10s|Checkerboard 커널이 커버하는 시간 (±)|
|Threshold|0.10~0.50|novelty curve 피크 감지 임계값|
|Distance|1.5~5.0s|최소 경계 간격|

**Grid search** (5,040 조합):

|파라미터|최적값|
|---|---|
|WS|2.0s|
|HS|1.0s|
|KS_SEC|6.0s (→ KS=6 frames)|
|Threshold|0.35|
|Distance|3.0s|
|**Macro F1**|**0.594**|

**Sequential tuning** (해석용 ablation):

- 각 파라미터 고정하고 하나씩 sweep → 파라미터별 sensitivity 확인
- 한계: 출발점에 따라 다른 local optimum으로 수렴 → narrative용으로만 활용

### 실험 3: LOOV CV — Method A Generalization

**목적**: 실험 2 config가 특정 게임에 과적합됐는지 측정

**방법**: 3게임 × leave-one-out

- 각 fold: 2게임 train → grid search 최적 config → 1게임 test

|Fold (test)|Train F1|Test F1|Best config|
|---|---|---|---|
|Game A|0.565|0.621|WS=2.0 HS=1.0 KS=6.0 Thr=0.35 Dist=1.5|
|Game B|0.649|0.445|WS=1.5 HS=1.0 KS=6.0 Thr=0.40 Dist=5.0|
|Game C|0.615|0.443|WS=2.5 HS=1.0 KS=5.0 Thr=0.30 Dist=4.0|

|지표|값|
|---|---|
|Full-data F1|0.594|
|LOOV mean F1|0.503|
|**Gap**|**0.091**|

**해석**:

- Game A는 일반화 잘 됨 (test > train)
- Game B, C는 급락 → 게임별 audio 특성 차이 존재
- **HS=1.0은 3개 fold 모두 선택** → 가장 안정적인 파라미터
- Gap=0.091 → 과적합 문제 존재

### 실험 4: Stem Fusion (Method B)

**목적**: 4개 스템(mixture/music/sfx/speech) NMS voting으로 과적합 완화

**방법**:

- WS/HS/KS_SEC/Dist는 Exp2 최적값 고정
- 스템별 Threshold 독립 탐색 (4^6 = 1,296 조합)
- Votes (최소 동의 스템 수) 탐색 {1, 2, 3, 4}
- LOOV CV 동시 수행

**Votes별 Best F1**:

|Votes|Best F1|
|---|---|
|1|0.421|
|**2**|**0.562**|
|3|0.524|
|4|0.205|

**Best config**: votes=2, thr(mix=0.35, mus=0.50, sfx=0.50, spe=0.40)

**Method A vs B 비교**:

||Method A|Method B|
|---|---|---|
|Full-data F1|**0.594**|0.562|
|LOOV mean F1|**0.503**|0.469|
|Gap|0.091|0.093|

**해석**:

- Stem fusion이 full-data F1도 낮고 gap도 개선 없음
- votes=2 → mixture + 스템 1개만 일치해도 통과 → mixture 단독과 큰 차이 없음
- sfx/speech thr이 높게 설정 (0.5) → 두 스템의 신뢰도가 낮음을 시사
- **"stem fusion이 implicit regularizer" 가설이 현재 데이터에서는 지지되지 않음**
