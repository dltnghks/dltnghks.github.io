NitroGen Vision Encoder의 학습 방법과 내가 생각하는 것의 차이는?
NitroGen에서는
![Pasted image 20260303104128](/assets/img/posts/2026-03-03-03-03-progress/pasted-image-20260303104128-d8636e29.png)

```
데이터 샘플
┌───────────────────────────────────────────────────┐
│ 관측 o ∈ R^{256×256}   +   GT 액션 a ∈ R^{16×24} │
└───────────────────────────────────────────────────┘
              │                      │
              │                      │
              │                (1) 가우시안 노이즈 샘플
              │                ε ~ N(0, I)
              │                      │
              │                (2) timestep 샘플
              │                t ~ shifted Beta (작은 t 우선)
              │                      │
              └──────────────┬───────┘
                             │
                (3) noisy action 생성
                a_t = (1 - t)·ε + t·a
                             │
                             │
        ┌────────────────────┴────────────────────┐
        │                                         │
(4) 조건 입력 만들기                         (5) 학습 타깃(정답 velocity)
o → 이미지 인코더 ψφ(o) = z_o                u* = a - ε
        │                                         │
        └────────────────────┬────────────────────┘
                             │
                   (6) 모델(정책) 예측
      v̂ = πθ( a_t , z_o , t )      (DiT가 velocity field 예측)
                             │
                   (7) 손실 계산 (MSE)
      L_CFM = E[ || v̂ - (a - ε) ||^2 ]
                             │
                   (8) θ, φ 업데이트
```

다음과 같은 구조로 학습이 되는데, 
- **a(정답 액션)** 과 **ε(노이즈)** 를 섞어서 **a_t** 를 만들고
- 모델은 **“이 a_t를 a쪽으로 밀어주는 속도(velocity) = a - ε”** 를 맞히도록 학습함.
- 관측 **o** 는 이미지 인코더 **ψφ** 로 임베딩해서 조건(condition)으로 넣음.
- **t** 는 작은 값이 더 자주 나오게 샘플링(shifted beta)해서 **초기(노이즈에 가까운) 구간의 학습을 더 강조**.


나는 장면 구분에 초점을 두기 때문에 이런 방식을 사용할 필요가 없다.
여기서는 액션 예측을 더 잘하기 위해 노이즈를 붙이고 그 방향으로 가기위한 속도를 계산한다.

## 조건부 속도장 (Conditional Velocity Field) 정의

이 모델의 목적은 노이즈($\epsilon$) 상태에서 실제 데이터($a$) 상태로 변하는 '흐름'을 배우는 것입니다. 이때 정의되는 속도장 $u^{\text{cond}}$는 단순히 **실제 데이터와 노이즈의 차이**로 정의된다.

$$u^{\text{cond}} = a - \epsilon$$

## 학습 목표: 손실 함수 (Loss Function)

모델은 실제 속도장($a - \epsilon$)을 최대한 정확하게 예측하도록 학습된다.

- **$\pi_\theta$ (DiT)**: 트랜스포머 기반의 확산 모델(Diffusion Transformer)로, 현재 상태에서 어디로 이동해야 할지(속도)를 예측한다.
    
- **$\psi_\phi$**: 이미지 인코더로, 관측 정보($o$)를 모델이 이해할 수 있게 변환한다.
    
- **손실 함수($\mathcal{L}^{CFM}$)**: 모델이 예측한 값과 실제 값($a - \epsilon$) 사이의 제곱 오차를 최소화한다.
    
    $$\mathcal{L}^{CFM}(\theta, \phi) = \mathbb{E}_{t, a, \epsilon} \left[ \| \pi_\theta(a_t, \psi_\phi(o), t) - (a - \epsilon) \|^2 \right]$$
    

## 학습의 특징

- **타임스텝 샘플링**: $t$를 균등하게 뽑는 것이 아니라, 작은 타임스텝(데이터에 가까운 시점)에 더 집중하는 **shifted beta distribution**을 사용하여 학습 효율을 높였다.
    
- **구조**: 시각적 정보를 처리하는 인코더와 액션의 흐름을 계산하는 DiT 구조가 결합된 형태다.

## 그렇다면 왜 action을 예측하는게 아닌가?
단순히 액션을 예측하는 방식(예: Behavior Cloning)과 NitroGen이 사용하는 **플로우 매칭(Flow-Matching)** 방식 사이에는 결정적인 차이가 있다.

가장 큰 차이는 **"결과를 한 번에 내놓느냐"**와 **"노이즈에서 점진적으로 만들어내느냐"**의 차이다.

---

### 1. 매핑 방식의 차이 (Direct vs. Iterative)

- **일반적인 액션 예측 (Regression):** 이미지($o$)를 넣으면 바로 액션($a$)이 튀어나온다. ($o \rightarrow a$). 모델은 "이 상황에선 이 팔 각도가 정답이야"라고 점을 찍는 방식이다.
    
- **NitroGen (Flow-Matching):** 처음에는 아무런 의미 없는 노이즈($a_0$)에서 시작한다. 모델($\pi_\theta$)은 이 노이즈를 **조금씩 깎고 다듬어서(Denoising)** 최종적인 액션($a_k$)으로 변형시킨다.
    

### 2. '멀티모달(Multimodal)' 분포 해결 능력

로봇 공학에서 가장 큰 문제는 **"정답이 여러 개일 때"**다.

- **일반 예측의 한계:** 장애물을 피할 때 '왼쪽'으로 가는 데이터와 '오른쪽'으로 가는 데이터가 섞여 있으면, 일반 모델은 그 중간인 '직진'을 선택해 버려 충돌할 수 있다 (Mean-averaging 문제).
    
- **플로우 매칭의 강점:** 노이즈에서 출발하여 데이터의 분포(Distribution)를 따라가기 때문에, "왼쪽으로 가는 흐름" 혹은 "오른쪽으로 가는 흐름" 중 하나를 명확하게 선택하여 생성할 수 있다. 복잡하고 다양한 정답이 존재하는 상황에서 훨씬 유리하다.
    

### 3. 수학적 효율성 (Flow vs. Diffusion)

NitroGen은 일반적인 확산 모델(Diffusion)보다 진화한 **Flow-Matching**을 쓴다.

- **확산 모델:** 노이즈가 제거되는 경로가 구불구불하고 복잡하여 계산이 많이 필요하다.
    
- **플로우 매칭:** $u^{\text{cond}} = a - \epsilon$으로 **직선 경로**를 학습한다. 덕분에 이미지 하단 설명처럼 **단 16단계(k=16)**의 적은 횟수로도 매우 정교한 액션을 뽑아낼 수 있다.

## 01 | 기초 개념

**내적 vs 코사인 유사도 vs 유클리드 거리**

내적이 크다고 벡터가 가까운 게 아님. 내적은 **방향 유사성 × 크기**를 동시에 반영.

```
내적         = |a||b|cosθ   — 방향 + 크기 모두 영향
코사인 유사도 = cosθ          — 순수 방향 유사성 (크기 정규화)
유클리드 거리 = ||a - b||      — 실제 공간상 거리
```

AI 논문의 `sim(a,b)`는 대부분 코사인 유사도. 정규화된 벡터끼리는 내적 = 코사인 유사도.

## 02 | InfoNCE

**van den Oord et al. (DeepMind, 2018)** — "Representation Learning with Contrastive Predictive Coding"

```
L = -E[ log( exp(sim(q,k+)/τ) / Σᵢ exp(sim(q,kᵢ)/τ) ) ]

→ loss 최소화 = Mutual Information 하한 최대화
→ I(X;C) ≥ log(N) − L   (N 클수록 하한 tight)
```

Temperature τ: 작을수록 차이 날카롭게, 클수록 안정적. 실전 범위 0.07~0.2.

## 05 | Temporal & Action-conditioned Positive

**Temporal**: `positive = (s_t, s_{t+k})` — 같은 trajectory, 시간적 근접  
**Action-conditioned**: `f(s_t, a_t) ≈ g(s_{t+k})` — action과 state의 인과관계

k는 "바로 다음 프레임"이 아닌 **"action 결과가 충분히 반영된 시점"**.

```
k 너무 작 (1~3)   : 거의 동일 프레임 → 학습 신호 약
k 적절   (5~15)   : action 결과 반영됨 ✓
k 너무 큼 (100+)  : 상황이 너무 달라짐
→ 권장: multi-scale k = [4, 8, 16] 동시 사용
```
