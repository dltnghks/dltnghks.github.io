# 네트워크 드라이브 Obsidian 무한로딩 해결

## 증상

- NAS(`\\192.168.1.4`)를 네트워크 드라이브(`Z:`)로 마운트해서 Obsidian 볼트로 사용하던 중 무한 로딩 발생
- 에러 메시지: **`file system operation timed out`**
- Obsidian이 파일을 읽거나 쓸 때 네트워크 드라이브 응답이 늦어 내부 타임아웃 초과

## 원인 분석

Obsidian은 Electron 기반으로, 파일 시스템 I/O에 내부 타임아웃이 존재한다. 네트워크 드라이브는 로컬 디스크보다 지연이 발생하기 때문에, 특히 아래 조건에서 타임아웃이 빈번하게 발생한다.

- **make-md 플러그인**: `main.js`가 5.7MB로 매우 무겁고, 볼트 전체를 스캔해 자체 Spaces 뷰를 구성함
- **dataview 플러그인**: 모든 노트를 인덱싱하는 과정에서 네트워크 I/O 집중 발생
- **`.makemd/` 캐시 파일**: `fileCache.mdc`, `superstate.mdc`가 시간이 지날수록 수 MB까지 비대해짐

## 해결 방법: 로컬 Clone + obsidian-git 자동 Sync

네트워크 드라이브를 직접 Obsidian 볼트로 사용하는 대신, **로컬에 클론한 후 GitHub을 통해 동기화**하는 방식으로 전환했다.

### 최종 구조

```
[로컬 C:\Users\dltrn\Github\obsidian-vault]
        ↕ obsidian-git (자동 commit & push / pull on boot)
[GitHub: dltnghks/obsidian-vault]
        ↕ 수동 pull (필요시)
[NAS Z:\999.노트]
```

### 진행 과정

#### 1. `.makemd/` 캐시를 git에서 제외

`.gitignore`에 추가:

```
# make-md plugin cache (binary, large, auto-generated)
.makemd/
```

기존에 추적되던 캐시 파일 제거:

```bash
git rm -r --cached .makemd/
```

#### 2. NAS 변경사항 commit & push

```bash
git add -A
git commit -m "chore: sync NAS state to GitHub, add .makemd to gitignore"
git push origin main
```

#### 3. 로컬로 clone

```bash
git clone https://github.com/dltnghks/obsidian-vault.git C:/Users/dltrn/Github/obsidian-vault
```

#### 4. obsidian-git 플러그인 설치

GitHub Releases에서 v2.37.1 수동 다운로드:

```
.obsidian/plugins/obsidian-git/
├── main.js
├── manifest.json
├── styles.css
└── data.json
```

`community-plugins.json`에 `"obsidian-git"` 추가.

#### 5. obsidian-git 주요 설정

| 설정 | 값 |
|------|-----|
| Auto pull on boot | ✅ |
| Auto backup after file change | ✅ |
| Auto save interval | 10분 |
| Pull before push | ✅ |
| Sync method | merge |

## 주의사항

- **`.makemd/` 폴더는 git으로 관리하지 않는다.** 자동 생성되는 캐시이므로 각 환경에서 독립적으로 생성된다.
- NAS는 더 이상 Obsidian의 직접 볼트로 사용하지 않는다. GitHub pull을 통해 최신 상태를 유지할 수 있다.
- obsidian-git의 자동 커밋 메시지 형식: `chore: vault backup YYYY-MM-DD HH:mm:ss`
