# Unity 거울 퍼즐 구현하기: RenderTexture로 만드는 반사 화면

거울을 닦고 좌우로 돌려 방 안을 살펴보는 퍼즐을 구현했다.

처음에는 반사 화면만 나오면 충분할 줄 알았다. 하지만 실제로 만들어보니 반사 원리뿐 아니라 카메라 구도, UI 배치, 유리 재질 표현까지 함께 고려해야 했다.

이번 글에서는 현재 구현한 구조와 작업하면서 알게 된 점을 정리한다.

## 구현 목표

거울 퍼즐에 필요한 동작은 다음과 같다.

- 얼룩을 청소하기 전에는 거울을 돌릴 수 없다.
- 얼룩을 모두 제거하면 드래그로 좌우 회전할 수 있다.
- 거울의 방향에 따라 비치는 방의 구역이 달라진다.
- 프레임과 반사면은 함께 회전하지만 배경은 고정된다.
- 원본 이미지의 점과 사선 무늬는 거울 표면에 항상 남는다.

현재는 특정 각도를 맞추면 완료되는 조건은 제거한 상태다. 거울을 청소하고 돌려서 관찰하는 기능에 집중했다.

## 1. RenderTexture

일반적인 카메라는 촬영 결과를 게임 화면에 출력한다.

하지만 카메라의 `Target Texture`에 RenderTexture를 지정하면, 촬영 결과를 다른 곳에 표시할 수 있는 이미지로 받을 수 있다.

```
일반 카메라
오브젝트 → 카메라 → 게임 화면

RenderTexture를 사용하는 카메라
오브젝트 → 카메라 → RenderTexture → 재질 또는 UI
```

게임 속 CCTV를 떠올리면 이해하기 쉽다. 복도를 촬영한 영상이 경비실 모니터에 표시되는 것과 같은 구조다.

거울도 이 방식을 사용했다. 방을 촬영한 영상을 RenderTexture에 담고, 거울 표면의 재질에 연결했다.

여기서 중요한 점은 **RenderTexture 자체가 반사를 계산하지는 않는다는 것**이다. 반사처럼 보이게 만드는 핵심은 카메라의 위치와 방향이다.

## 2. 카메라를 두 개로 나눈 이유

이번 구현에서는 카메라 두 개를 사용했다.

|카메라|역할|
|---|---|
|`MirrorReflectionCamera`|거울에 비칠 방의 일부를 촬영한다.|
|`MirrorStageCamera`|배경과 거울을 합친 최종 화면을 촬영한다.|

전체 흐름은 다음과 같다.

```
CH1 반사용 환경
        ↓
반사 카메라
        ↓
반사 RenderTexture
        ↓
거울 표면에 표시
        ↓
배경 + 프레임 + 반사면
        ↓
표시용 카메라
        ↓
최종 RenderTexture
        ↓
퍼즐 UI의 RawImage
```

카메라를 나누면 두 가지 문제를 독립적으로 조정할 수 있다.

- 거울 안에 어떤 구역이 보이는가?
- UI 안에서 거울이 얼마나 크게 보이는가?

반사 구도를 수정하기 위해 UI 배치를 바꾸거나, UI 크기를 맞추기 위해 반사 카메라를 옮길 필요가 줄어든다.

## 3. 거울 프레임과 반사면 분리하기

원본 UI 이미지는 배경, 프레임, 유리가 한 장으로 합쳐져 있었다.

이 상태에서 이미지를 회전시키면 뒤쪽 배경까지 함께 돌아간다. 그래서 배경과 프레임을 분리하고, 유리 부분은 실시간 반사 영상을 표시하는 메시로 대체했다.

```
MirrorPuzzleStage
├─ MirrorArtworkBackground
├─ MirrorPivot
│  ├─ MirrorFrame
│  └─ MirrorSurface
├─ MirrorStageCamera
├─ MirrorReflectionCamera
└─ CH1FixedStageAnchor
```

`MirrorPivot`이 회전 중심이다. 프레임과 반사면을 그 아래에 두어 부모 하나만 회전시켜도 두 요소가 함께 움직이도록 했다.

거울의 안쪽 모양이 팔각형이므로 반사면도 팔각형 메시로 만들었다. 덕분에 반사 영상이 프레임 모서리 밖으로 튀어나오지 않는다.

이번에 분리한 이미지 에셋은 이미지 편집 모델로 재구성한 결과이므로 원본과 미세한 차이가 있다.

## 4. 드래그 입력을 회전 각도로 변환하기

거울은 마우스의 가로 이동량에 따라 Y축으로 회전한다.

핵심 코드는 다음과 같다.

```
SetYaw(currentYaw + eventData.delta.x * degreesPerDragPixel);
RenderStage();
```

`degreesPerDragPixel`은 드래그 감도다. 마우스가 같은 거리만큼 움직여도 이 값이 클수록 거울이 더 많이 돌아간다.

회전을 적용할 때는 최소·최대 각도를 제한한다.

```C#
private void SetYaw(float yaw)
{
    currentYaw = Mathf.Clamp(yaw, minimumYaw, maximumYaw);

    if (mirrorPivot != null)
    {
        mirrorPivot.localRotation =
            Quaternion.Euler(0f, currentYaw, 0f);
    }
}
```

이 단계만 구현하면 거울의 외형은 회전하지만, 비치는 화면까지 자연스럽게 달라지지는 않는다. 다음으로 반사 카메라를 연결해야 한다.

## 5. 거울 각도에 따라 반사 카메라 계산하기

반사 카메라는 관찰 카메라의 위치와 시선을 거울 평면에 대해 대칭으로 반사한 위치에 배치한다.

먼저 거울의 앞쪽 방향을 구한다.

```C#
Vector3 mirrorNormal = -mirrorPivot.forward;
```

그다음 거울 중심에서 관찰 카메라까지의 벡터를 반사한다.

```C#
Vector3 cameraOffset =
    stageCamera.transform.position - mirrorPivot.position;

Vector3 reflectedPosition =
    mirrorPivot.position + Vector3.Reflect(cameraOffset, mirrorNormal);
```

시선 방향과 위쪽 방향도 같은 방식으로 계산한다.

```C#
Vector3 reflectedForward =
    Vector3.Reflect(stageCamera.transform.forward, mirrorNormal);

Vector3 reflectedUp =
    Vector3.Reflect(stageCamera.transform.up, mirrorNormal);

Quaternion reflectedRotation =
    Quaternion.LookRotation(reflectedForward, reflectedUp);
```

거울이 회전하면 법선 방향이 바뀌고, 이에 따라 반사 카메라의 위치와 방향도 달라진다.

다만 현재 구현은 별도의 화각과 텍스처 매핑을 사용하는 **퍼즐용 반사 연출**이다. 현실 거울과 완전히 동일한 투영을 구현한 것은 아니다.

### 거울 뒤의 벽이 시야를 가리는 문제

반사 계산으로 얻은 가상 카메라는 거울 뒤쪽에 위치할 수 있다. 이때 뒤쪽 벽이 반사 화면을 가릴 수 있다.

이를 처리하기 위해 거울 평면을 기준으로 클리핑 평면을 만들고, `CalculateObliqueMatrix()`를 통해 카메라 투영에 적용했다.

쉽게 말해 반사 화면에 필요 없는 거울 뒤쪽 공간을 잘라내는 처리다.

## 6. 촬영 순서가 중요하다

카메라 위치를 계산한 뒤에는 다음 순서로 렌더링한다.

```
UpdateReflectionCameraPose();
reflectionCamera.Render();
stageCamera.Render();
```

1. 반사 카메라가 방의 영상을 갱신한다.
2. 거울 표면이 갱신된 영상을 표시한다.
3. 표시용 카메라가 거울 전체를 촬영한다.

순서가 반대라면 최종 화면에 이전 반사 영상이 보일 수 있다.

현재는 두 카메라의 자동 렌더링을 끄고, 팝업을 열거나 드래그할 때 직접 갱신한다. 고정된 환경을 보여주는 현재 퍼즐에 맞춘 방식이다.

## 7. 반사 영상만으로는 거울처럼 보이지 않았다

처음에는 반사 영상을 Unlit 재질에 그대로 표시했다.

영상은 잘 보였지만, 결과는 거울보다 모니터나 액자에 가까웠다. 표면이 유리라는 시각적 단서가 부족했기 때문이다.

이를 보완하기 위해 `MirrorGlass.shader`에 다음 표현을 추가했다.

- 옅은 청록색 틴트
- 대각선 반짝임
- 시선 각도에 따른 반짝임 변화
- 가장자리의 약한 음영

반사된 물체는 그대로 읽을 수 있도록 효과를 약하게 적용했다.

반짝임은 반사 영상의 좌표가 아니라 거울 표면의 UV를 기준으로 계산한다. 그래서 방의 영상과 별개로 유리 표면 위에 놓인 효과처럼 보인다.

## 8. 고정 무늬와 청소용 얼룩 구분하기

원본 거울 이미지에는 점과 짧은 사선 자국이 있었다.

처음에는 이를 청소용 얼룩으로 연결했지만, 이 자국들은 제거 대상이 아니라 거울에 항상 남아 있어야 하는 디테일이었다.

따라서 두 요소를 분리했다.

|구분|구현 방식|청소 후|
|---|---|---|
|원본의 점·사선 무늬|거울 셰이더에서 텍스처 합성|유지|
|청소용 얼룩|`MirrorStainTarget`으로 관리|제거|
|유리 반짝임|셰이더에서 계산|유지|

고정 무늬는 반사 영상 위에 알파 합성한다.

```
color = lerp(color, marking.rgb, marking.a);
```

이때 무늬는 거울 표면 좌표를 사용한다. 거울 안의 사물이 움직여도 무늬는 사물을 따라 움직이지 않고, 거울 표면에 붙어 있게 된다.

## 9. 청소가 끝나야 회전할 수 있도록 만들기

청소용 얼룩에는 `MirrorStainTarget`을 붙였다.

올바른 아이템을 사용하면 얼룩을 숨기고 `Cleaned` 이벤트를 보낸다. 팝업은 이 이벤트를 받아 남은 얼룩이 있는지 확인한다.

```
얼룩이 남아 있음
    → 회전 불가

모든 얼룩 제거
    → 드래그 회전 가능
```

현재 청소용 얼룩은 UI 요소다. 얼룩이 있는 동안 회전을 막으므로, 청소 중에는 거울 회전에 맞춰 얼룩 위치를 갱신할 필요가 없다.

추후 청소 중에도 거울을 돌릴 수 있게 바꾼다면, 청소용 얼룩 역시 회전하는 거울 표면을 따라가도록 수정해야 한다.

## 10. 구현하면서 주의했던 부분

### RenderTexture와 표시 영역의 비율

가로형 거울에 정사각형 영상을 그대로 붙이면 사물이 옆으로 늘어난다.

반사면의 가로세로 비율에 맞춰 반사 RenderTexture를 조정하고, 최종 영상과 UI 표시 영역의 비율도 맞췄다.

### 거울이 화면 밖으로 잘리는 문제

표시용 카메라가 너무 가까우면 거울의 위아래가 잘린다.

표시용 카메라는 직교 투영을 사용하고, 회전 가능한 범위에서도 프레임 전체가 화면 안에 들어오도록 크기를 조절했다.

### 환경 복제본의 유지보수

현재 반사 카메라는 실제 플레이 중인 CH1 씬이 아니라 `CH1MirrorEnvironment.prefab`을 촬영한다.

독립적으로 테스트하기에는 편하지만, 실제 맵이 바뀌면 반사용 환경도 갱신해야 한다.

장기적으로는 공용 환경 프리팹을 사용하거나 실제 씬을 직접 촬영하는 방식으로 개선할 여지가 있다.

## 마무리

이번 거울 퍼즐의 핵심은 다음 네 가지다.

1. **RenderTexture로 카메라 영상을 거울 표면에 표시한다.**
2. **거울 회전에 맞춰 반사 카메라의 위치와 방향을 계산한다.**
3. **반사 영상과 유리 표면 표현을 분리한다.**
4. **시각적 디테일과 청소 상호작용을 별도로 관리한다.**

단순히 영상을 붙이는 것만으로 반사 화면은 만들 수 있었다. 하지만 거울처럼 느껴지게 하려면 프레임, 유리 표현, 화면 비율, 회전 구도까지 함께 맞춰야 했다.
